# Codebase review

Reviewed and rechecked against the current worktree on 2026-10-18. Findings are ordered by impact; these are code paths and risks, not claims of observed exploitation. Statuses below describe code and local tests; they do not mean the changes are deployed.

1. **High — A failed auth check can erase local work. Resolved in worktree.** [`getCurrentUser`](../frontend/src/api.js) now distinguishes confirmed guest state from a failed request, and startup keeps cached work when authentication is unavailable. Focused frontend auth tests cover the distinction. A full browser recovery task remains useful.
2. **High — PDF compilation has no timeout. Resolved in worktree.** [`compile_guide_pdf`](../backend/app/services/study_files.py) now has a configurable deadline, output cap, process-group termination, and bounded semaphore wait. Strict study-file tests cover error parsing and compile failures; live Tectonic behavior still depends on the installed binary.
3. **High — Login throttling is easy to bypass. Resolved in worktree.** [`login`](../backend/app/api/auth.py) checks per-client and per-identifier buckets; [`InMemoryRateLimiter`](../backend/app/security/rate_limit.py) hashes and bounds identities. Existing authentication tests exercise rate limits. The limiter is single-process; multi-worker deployments still need a shared gateway/store policy.
4. **High — Some API bodies have no size cap. Resolved in worktree.** [`RequestSizeLimitMiddleware`](../backend/app/middleware/request_size.py) applies a default ceiling, counts streamed bytes, and grants explicit upload/library allowances. The full backend suite includes request-limit regressions. Reverse-proxy limits remain deployment-specific.
5. **Medium — Local save fallbacks overstate durability. Partially resolved.** Server class-creation failures no longer masquerade as local successful creation, and browser file handling reports local-only/unavailable persistence. There is no general background sync queue for every local draft; verify each affected UI before describing it as durable.
6. **Medium — The spend ledger is incomplete and starts with someone else's number. Resolved for the configured study-generation provider; broader provider use remains excluded.** The balance is blank until a snapshot is entered, scope exclusions are disclosed, and the admin ledger now shows per-material totals including retries, known subtotals, and unpriced calls. Gemini Live/media and direct provider use remain outside this ledger. No unknown amount is represented as `$0`.
7. **Medium — “Continue studying” does not track activity. Resolved in worktree.** Continue uses the last opened ready material scoped to the active account/class, and the guide reopens its last section. The browser test covers choosing the older last-opened item over a newer material.
8. **Low — Quality gates miss visible regressions. Partially resolved.** Focused backend/frontend suites and a production build were run. Firefox previews were inspected at 1440, 390, and 320 CSS pixels for a representative guide, chat, and cost ledger; this is a manual visual check, not CI browser automation, a 400% zoom/screen-reader audit, or full-course coverage. `ruff` is not installed in the active environment; do not treat the previous 342-finding audit as a current count.
9. **High learning impact — Generated output can pass structural checks and still mislead. Partially resolved.** Math/chemistry, Markdown, tables, IDE-style code, sanitized diagrams, activity fallbacks, mini-quiz key withholding, and PDF export paths have focused checks. High-risk claims, answer correctness, arrow meaning, all saved SVGs, and source-revision parity are not independently established. The user previously rejected a reviewer model; none is used as an automatic factual gate.
10. **Medium learning impact — Core actions are scattered across study surfaces. Partially resolved.** The guide now paginates, links its sources, offers an in-guide section check and source-grounded chat, and surfaces its own due state. A unified cross-material Review-due queue and a new validated question after missed quiz answers remain open; complete desktop/phone screen-reader tasks still need people.

## Implementation order and boundaries

Findings 1–4 and 7 are implemented and locally covered. Finding 5 is partial; 6 is complete for this Jot-configured text-generation ledger but explicitly excludes other provider spend; 8–10 remain partial for the reasons above. The next engineering priorities are a shared question-family mapping for delayed guide review, browser automation with keyboard/assistive checks, and deterministic/source-human review of high-risk generated claims. These are release limitations, not completed work.

The browser and backend have separate ownership under [AGENTS.md](../AGENTS.md). Any new guide chat or review endpoint needs the shared contract recorded in [frontend design](frontend-design.md) and [backend design](backend-design.md). The browser should receive authorized rendered content and opaque identifiers, while the backend resolves guide/source context, provider configuration, and access policy. New libraries are acceptable when they improve domain diagrams or code visualization; record their purpose, keep them lazy where practical, and test a fallback.

The root README's Linux/macOS and Windows virtual-environment setup commands were corrected. No live provider calls or production changes were made. Local Firefox visual checks were limited to representative fixtures and do not establish WCAG conformance or semantic correctness. Pre-existing untracked artifacts, `backend/uv.lock`, and `sqlite3` were left untouched.
