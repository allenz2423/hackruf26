# Codebase review

Reviewed the updated frontend, backend, tests, and deployment files on 2026-10-18. Findings are ordered by impact; these are code paths and risks, not claims of observed exploitation.

1. **High — A failed auth check can erase local work.** [`getCurrentUser`](../frontend/src/api.js#L19) turns every `/api/auth/me` error into `null`. On startup, [`applyAuth(null)`](../frontend/src/app.js#L212) deletes cached classes and uploaded files. A transient API failure can therefore destroy browser-only classes and unsynced sources. Distinguish a confirmed guest from an unreachable server before clearing data.
2. **High — PDF compilation has no timeout.** [`compile_guide_pdf`](../backend/app/services/study_files.py#L2001) holds a global semaphore while `subprocess.run` waits without a timeout or output bound. The `STUDY_PDF_TIMEOUT_SECONDS=120` value in [`Dockerfile`](../Dockerfile#L47) and [`compose.yaml`](../compose.yaml#L22) is unused. A stuck compiler can block every later PDF job; enforce a wall-clock limit and bounded output.
3. **High — Login throttling is easy to bypass.** [`login`](../backend/app/api/auth.py#L115) keys its limiter by IP *and* submitted identifier. Rotating identifiers avoids the per-key limit while each miss runs scrypt; the limiter also retains a key for each new identifier until cleanup. Add a per-IP budget alongside per-account limits. The existing [test](../backend/tests/test_auth.py#L119) repeats only one identifier.
4. **High — Some API bodies have no size cap.** [`RequestSizeLimitMiddleware`](../backend/app/middleware/request_size.py#L38) returns `None` for auth, admin, and learning routes, so their JSON bodies can be read before field validation with no application limit. Apply a default cap and narrower exceptions for uploads. A separate deployment proxy may impose its own limit; that configuration was not available here.
5. **Medium — Local save fallbacks overstate durability.** [`createClass`](../frontend/src/classes.js#L248) converts any server failure into a local class, and the caller immediately opens it as created ([`app.js`](../frontend/src/app.js#L560)). Failed local file writes are discarded before the Library reports files added ([`library.js`](../frontend/src/library.js#L491)). Show unsynced state and require a successful browser write before claiming a file is saved.
6. **Medium — The spend ledger is incomplete and starts with someone else's number.** Only the OpenAI-compatible client receives a [`UsageLedgerRecorder`](../backend/app/main.py#L212); Gemini media calls in [`gemini_content.py`](../backend/app/services/gemini_content.py#L5117) and Live calls are outside it. The [admin form](../frontend/src/app.js#L2083) is prefilled with `$63.86` for every installation. Label the ledger's scope and leave an unknown balance blank.
7. **Medium — “Continue studying” does not track activity.** [`study.js`](../frontend/src/study.js#L856) selects the newest ready material and calls it “Pick up where you left off.” A newly generated set can replace the one the learner was using. Use last-opened or unfinished activity, or rename the action.
8. **Low — Quality gates miss visible regressions.** At the original audit, frontend unit tests and the production build passed, but there was no browser end-to-end or accessibility test command in [`package.json`](../frontend/package.json). The build emitted several large chunks, and `ruff check backend/app backend/tests --statistics` reported 342 findings (341 long lines, one mutable `ContextVar` default). Recheck those baselines, add focused browser coverage, and make lint/build-size budgets actionable.
9. **High learning impact — Generated output can pass structural checks and still mislead.** Guide SVGs have [sanitization and phone-text checks](../backend/app/services/study_guide_visual_preview.py#L61), and math has a [safe renderer](../frontend/src/math.js), but the guide release path does not independently verify arrow meaning, cited claims, or browser/PDF visual agreement. The quiz-review tutor returns [plain text with LaTeX](../backend/app/services/study_tutor.py#L21), so richer explanations need a defined display contract. Review actual rendered examples across text, math, code, chemistry, SVG, animation, and exports; preserve a safe readable fallback.
10. **Medium learning impact — Core actions are scattered across study surfaces.** The Study landing card's “Pick up where you left off” uses the [newest ready item](../frontend/src/study.js#L856); due review starts from [Progress](../frontend/src/progress.js#L701); guide clarification requires leaving the guide. This does not prove every page has a deep-scroll problem, but it gives concrete tasks for a desktop/phone navigation audit. Make the next useful action, source evidence, section jump, and help reachable near the content they serve.

## Fix contracts and proof of completion

| Finding | Required behavior | Focused verification |
| --- | --- | --- |
| 1. Auth cleanup | A confirmed guest/logout may clear account-scoped cache. A timeout, 5xx, or offline `/api/auth/me` result keeps browser-only work intact and shows a retry state. | Simulate network failure on startup with an unsynced class and file; verify neither is deleted. Test true logout and account switch separately. |
| 2. PDF compiler | Enforce a real wall-clock deadline, bounded output and process cleanup while holding the compile lock for the shortest safe time. Return a recoverable guide-export error. | Make a fake compiler hang, then prove a later export can proceed after timeout. |
| 3. Login throttling | Limit both per client and per account identifier; bound limiter key growth and use the trusted proxy/IP policy already configured by the app. | Rotate many identifiers from one client and verify throttling before expensive password work; confirm legitimate clients can recover after the window. |
| 4. Request bodies | Apply a modest default cap to JSON mutation routes, with explicit larger allowances for upload and other documented exceptions. Count streamed bytes as well as `Content-Length`. | Oversized auth/admin/learning bodies return a consistent 413; normal requests and bounded uploads still work. |
| 5. Local durability | A local fallback is labeled unsynced. Report success only after the browser write succeeds, and provide a visible retry/sync route after server recovery. | Fail API and IndexedDB independently; verify the UI never claims an unsaved file or class is safely stored. |
| 6. Spend ledger | Show which provider operations are tracked and an unknown balance until an administrator supplies one. Never present a hard-coded starting balance as installation data. | Fresh installation has no invented balance; out-of-scope calls are labeled, and a manual snapshot survives reload. |
| 7. Continue | Resume the last opened unfinished material and its section when available; use an honest Latest label otherwise. Keep this private per account. | Open an older guide, generate a newer set, return to Study, and verify the correct destination. |
| 8. Quality gates | Add a small browser smoke suite for study entry, guide, chat, quiz review, and mobile navigation; run axe or equivalent plus manual screen-reader checks for critical flows. | CI runs the smoke suite and build; baseline lint debt is recorded separately so new failures are actionable. |
| 9. Generated formatting | Validate supported blocks and sanitized SVG, inspect rendered phone/desktop/PDF fixtures, and use clear text fallbacks for unsupported content. Claims and visual relationships receive source review beyond schema checks. | Fixtures cover malformed math, chemical notation, long code, lists, tables, tiny/clipped SVG labels, wrong arrow direction, animation states, and browser/PDF parity. |
| 10. Information access | Use a consistent action hierarchy and local navigation so a learner can resume, review due work, find help, and inspect evidence without searching through unrelated controls. | Task tests at phone and desktop widths record whether these actions can be found and completed; check keyboard focus and 400% reflow. |

## Implementation order and boundaries

Start with findings 1–5 because they affect data integrity, abuse resistance, and guide availability. Then address generated-content trust and presentation (9), followed by the study path (7 and 10). Keep the spend ledger and test infrastructure work explicit rather than hiding it inside a visual redesign. Some learning and navigation outcomes need actual learner task tests; code completion alone cannot establish improved retention or usability.

The browser and backend have separate ownership under [AGENTS.md](../AGENTS.md). Any new guide chat or review endpoint needs the shared contract recorded in [frontend design](frontend-design.md) and [backend design](backend-design.md). The browser should receive authorized rendered content and opaque identifiers, while the backend resolves guide/source context, provider configuration, and access policy. New libraries are acceptable when they improve domain diagrams or code visualization; record their purpose, keep them lazy where practical, and test a fallback.

The root [README](../README.md#L42) also uses Windows virtual-environment paths in its main Linux/macOS setup and test commands. I did not validate external AI behavior or run a live browser session. Existing untracked files were left untouched.
